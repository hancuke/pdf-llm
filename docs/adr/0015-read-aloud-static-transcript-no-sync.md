# ADR-0015 — 朗读保持静态副本，不做音频同步高亮

朗读的「朗读文字视图」刻意维持为**静态、可点击的选区副本**，不与音频播放进度做逐句/逐词同步高亮。背景：成熟产品（Edge Read Aloud、Google Play Books）普遍做当前句/词高亮，但本应用经 Edge TTS 代理只回一段 audio blob，不含词/句时间戳；要做同步须升级代理返回词时间戳（架构级改动），或改为分句合成（每句一次请求、句间出现微停顿、请求数上升）。本轮重设计明确朗读为**选区作用域的「随听」**（对齐 LLM 选中聚焦核心），且用户选择不投入同步能力，故维持现状。

**Considered Options**
- 词级卡拉OK：让代理返回词时间戳，真正逐词高亮 —— 需改 TTS 架构，成本最高，未采纳。
- 句级同步（分句合成）：按句拆分逐句合成，天然得句边界 —— 可同时支持句高亮与句跳转，但有微停顿+请求膨胀，用户未采纳。
- 保持静态副本：仅可点击查词，零后端改动 —— **采纳**。

**Consequences**
- 传输条**不提供** ⏮/⏭ 句跳转（无句边界时间戳）；逐词跟读/karaoke 不存在。若日后要补，须先解决时间戳来源（属 ADR 级工作，不是面板 bug）。
- 朗读文字视图的价值收敛为「点词查音标 + 单词语音」的词汇面，而非跟读面；这正是本应用相对成熟听书产品的差异化落点。
- 选区作用域体验一致、实现成本低、不引入后端依赖（与 ADR-0001 一致）。
